# F3: a tighten that can't lock you out

Decision Q4 (2026-11-27, "Proposal or 1-hour expiry"): an unconfirmed
`rv host mode <host> block` that would stop agents never locks an agent out.

## Behaviour

`rv host mode <host> block` of a host that is not already enforcing:

| Who asks | Result |
| --- | --- |
| Owner at a terminal | Owner check (Touch ID or password), then permanent. It replaces any agent block on that host. A refused check changes nothing (exit 77). |
| Agent, another agent's host | Block for one hour, then the stored mode is back on its own. |
| Agent, its own host (marker such as `CLAUDECODE`) | Proposal, nothing changes (exit 77). |
| No agent marker at all | Proposal, nothing changes (exit 77). |
| Host is `off` | Proposal, nothing changes (exit 77). An agent cannot wire a host back in. |

A block of a host that already enforces is stored as asked, with no check.
Asking again while an agent's block is open does not extend it. Ending
that block early is a loosening, so it needs the owner.

## Behaviour change under observe

Before F3, `block` needed no check, including under global `guard.mode`
observe. Now a block of any host that is not already enforcing follows the
table above: it asks for the owner check at a terminal, and without one it
becomes a one-hour block or a proposal. Four existing `HostCommandTests`
now pass an owner requester for this reason.

## Output

One-hour block:

```
grok  block  wired  until 15:12
  An agent's block ends on its own after an hour; then grok is back to observe.
  To keep it blocked, you type:
→ rv host mode grok block
```

`--json`: `{"host":"grok","mode":"block","schema":"rv.host-mode.v1","then":"observe","until":"2025-11-27T15:12:00Z","wiring":"wired"}`

Proposal (exit 77, stdout):

```
⏺ asks  block grok: you decide
  Blocking grok would stop the agent that asked, so nothing changed.
  To do it, you type:
→ rv host mode grok block
```

The second line follows the reason:

- own host: `Blocking grok would stop the agent that asked, so nothing changed.`
- no marker: `rv can't tell which agent asked, and blocking grok could stop it, so nothing changed.`
- off host: `grok is off; an agent can't wire it back in as block, so nothing changed.`

`--json` (exit 77): `{"host":"grok","mode":"block","proposed":true,"reason":"unknown-caller","schema":"rv.host-mode-proposal.v1"}`.
`reason` is `own-host`, `unknown-caller` or `host-off`.

`rv host list` shows `until HH:MM` on a host under an agent's block, and
`until` (ISO 8601) in `--json`.

## Storage

`guard.temporary_blocks.<host>` = `{"from": <unix s>, "until": <unix s>}`,
beside `guard.hosts.<host>`, never over it. Every reader resolves the window
against the clock (`GuardModeResolution.resolve(…, now:)`), so ending needs
no write and no rvd, and it survives restarts. A window longer than an hour,
a clock set back before `from`, or a malformed record all read as closed.
The ladder is `RV_GUARD_MODE=enforce` > open temporary block >
`guard.hosts` > `guard.mode` > enforce.

## Known gap

The C hook's daemon-down fallback does not read the window and uses the
stored mode. That fails toward unchanged or looser than the agent's block,
never toward a lockout. It is recorded in the CHANGELOG.
