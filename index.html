Who gets to say no

Coding agents run our shells now. The checkpoints we built check the wrong moment.

Chris Karani · Aug 2026 · DRAFT v7

I built a hook that blocks destructive shell commands before Pi's bash tool runs. Mac only, Apple Silicon, macOS 26. It's called rv.

It's regex on the command string. Not a sandbox, not OS-enforced, not expansion-aware. I want to say that up front because the rest of this post is about why even that much is worth having.

First, what a deny actually looks like. An agent proposes git reset --hard. The hook fires and rv sends back:

Blocked git reset --hard (core.git/reset-hard). Run it in Terminal, or rv allow-once.

Pi blocks the command. It never runs. Same for rm -rf ./src, git push --force, find / -delete, redirects onto /etc. Two packs are on by default: core.filesystem and core.git. There's a catalog of ~99 more, opt-in; system.disk is off on purpose. And some things you'd want blocked are allowed: rm -rf /tmp/build runs fine (temp dirs are safe), so does git push --force-with-lease and git stash drop.

Some things slip through. A python script that execs rm never looks like rm to the hook. A non-bash tool never meets it at all. Skip or disable the hook and rv sees nothing. Its grade is hook-level, full stop.

Why build this at all? In July an agent on Windows was asked to clear an app's tmp cache. The command contained a variable inside double quotes, so the outer shell expanded it to nothing between approval and execution. What got approved was a cache clear; what ran deleted /bin, /boot, /etc, and the user's home directory for four minutes. When the agent itself noticed and tried to kill the runaway rm, its own safety layer refused, because killing the cleanup counted as interfering with the workload. The human stopped it by shutting down WSL entirely.

That's issue 82165 against Claude Code, still open, reported by the person who lost the files. There are others in the same tracker: a quoting mistake that turned an approved file copy into rm -rf /* on a production server, a home directory wiped by an rm -rf * that ran after the agent made a folder literally named ~, days of uncommitted work gone from one case-flipped path on a case-insensitive filesystem.

I'm not claiming rv would have caught all of those. It matches the command text after stripping sudo and env wrappers; it does not expand variables, and it doesn't see what bash does with quotes or globs. rm -rf $EMPTYVAR dies because the rule matches rm -rf, not because rv solved expansion. But there's a gap between "checkpoint saw something" and "shell did something," and right now almost nothing lives in that gap. This is a small thing that lives there.

On prompts as a defense: Anthropic published that users accept 93% of permission prompts, and their auto-mode classifier still misses about 17% of overeager actions. Those numbers are why I didn't build another dialog.

The design calls I argued with myself over:

Garbage payload means block. If rv can't read what the hook sent, the command doesn't run. Unknown commands mean allow, deliberately: two packs can't judge everything, and a guard that blocks what it doesn't recognize gets turned off within the hour, which is worse than it not existing.

There's an unlock path, but only on Grok right now. Deny something you meant to run and you can mint a one-time allowance for that exact command in that exact folder. Pi and OpenCode can't do this yet because their hook payloads don't carry the working directory. Pi actually exposes ctx.cwd and our adapter drops it — that's ours to fix, first thing on the list. Until then, no unlock rather than a global bypass.

Two disclosures. Anonymous usage counters are wired to PostHog: install events, daily counts, pack IDs, host wiring. Never command text or paths, evaluation happens locally. No API key ships in the binaries, so nothing sends today, but the code is there and now you know. And rv installs three executables plus a LaunchAgent (rvd, the evaluate service). Uninstall takes all of it back out.

Install:

curl -fsSL INSTALL_URL | sh

The script writes three binaries to ~/.local/bin, hook files under rv-owned names in your agents' config folders, and the LaunchAgent plist. Foreign hooks untouched.

Here's what I want from posting this: break it. Run weird commands through your agent and tell me what got denied that shouldn't have been, or worse, what slipped through. The packs will grow from real misses, not from me guessing.
