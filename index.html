I built a guard for my coding agent's shell, because it almost ate a directory

rv sits between Pi (or Grok, or OpenCode) and the shell commands it's about to run.

Chris Karani · Aug 2026 · DRAFT v2

Last month I asked my coding agent to clean up a build folder and watched it run rm -rf on a path it had guessed. I caught that one. I didn't catch an earlier one, and I'm not going to pretend the files were backed up.

So I wrote rv. It's a small Mac tool that sits between your coding agent and its shell hooks. When Pi is about to run a shell command, rv looks at it first. Recursive deletes, force-pushes, stuff like that gets blocked before it runs, with a short note about which rule fired.

I want to explain a few decisions because they're the part you'd want to know before trusting this thing.

It fails closed

If rv can't understand what the hook sent it, it blocks. That sounds obvious but most tools do the opposite, because blocking feels like breaking. A guard that goes quiet when things get weird isn't a guard, it's decoration.

Blocking isn't a dead end

If it stops something you actually meant to run, you unlock that exact command for that folder, once. Next time it asks again. I went back and forth on this a lot. "Trust this agent forever" was easier to build and it's how you end up right back where you started.

Nothing leaves your machine

The evaluation happens locally. No analytics, no telemetry, your commands are not anyone's data. This shouldn't be remarkable but here we are.

It doesn't claim more than it does

rv works at the hook layer. It is not a sandbox. If some process skips the hook entirely, rv never sees it. I could have blurred this in the marketing and nobody would have checked for months. But you'd find out eventually, probably at the worst possible time, so: hook-grade, that's what it is, that's all it claims to be.

Install

curl -fsSL INSTALL_URL | sh

Two binaries, rv setup, done. Setup only touches rv's own files, so if you already have hooks from something else it leaves those alone. There's an rv doctor for when things seem off, and uninstall actually uninstalls.

Works with Pi, Grok, and OpenCode today. Shell commands only for now — no file-edit hooks yet. macOS 26 on Apple Silicon, because that's the machine I have and I'd rather support one thing properly than three things approximately.

Here's what I actually want out of posting this: break it. Run weird commands through your agent. Tell me what got denied that shouldn't have been, or what slipped through that really shouldn't have. The rules are deliberately few. They'll grow from real misses, not from me sitting around imagining disasters.
