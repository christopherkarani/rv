What's the conservative design for a guard?

Notes from a 16-module Swift 6 package that blocks destructive agent shell commands. Hook-grade, not a sandbox.

Chris Karani·Aug 2026·DRAFT v2

I spent the last few months writing a Swift program called rv. It sits on a Mac and blocks destructive shell commands before coding agents like Pi, Grok, or OpenCode run them. There's a longer story on GitHub Pages if you want it, but this post is about the Swift engineering, because that's the part I'd want to read.

What's the conservative design for a guard? The obvious move is to block anything you don't recognize, and I don't think that's right. Two default-on packs can't judge everything, and a guard that blocks what it doesn't recognize gets disabled within the hour. So unknown commands default-allow.

The engine is deliberately boring: you normalize the command string, strip sudo and env wrappers, and quick-reject on keywords, then safe patterns first, destructive second, else allow.

But evaluation wasn't the interesting problem. Mapping was. Pi wants a TS extension, OpenCode a JS plugin, Grok a JSON hook file. Instead of per-host branching, there's one switch over a closed Decision enum in a hook mapper, with small host codecs turning the result into each host's native block format, so adding a fourth host means writing one codec.

This is fail-closed as copy, not just behavior. An unreadable hook payload blocks the command, and the deny sentence lives in exactly one module shared by the hook layer and the TUI:

Blocked git reset --hard (core.git/reset-hard). Run it in Terminal, or rv allow-once.

What happens if the daemon is down or versions skew? Evaluation falls back to in-process rather than letting the command through. There's no allow-because-XPC-missed, and that constraint shaped a lot of the architecture.

Typed throws finally earn their keep. Regex compilation throws PatternCompileError with the offending pattern attached, and the compiler makes every call site deal with it. No try? swallowing a bad rule into silence; a malformed pack pattern fails loudly at load.

The shape of it is 16 SPM modules, strict language mode 6, one external dependency (argument-parser). Value types go all the way down through the core: Domain, Engine, and Packs are structs and enums only. Classes exist at exactly two kinds of edges: actors where shared mutable state is real (the allow-once store, the service runtime), and the XPC boundary.

And the unglamorous bit I like most is tools/gate.sh, which infers which test targets to run from your git diff. Touch RVEngine and you run RVEngineTests, and it refuses to exit green if it would run zero tests.

The numbers, since people ask: about 14k lines of source, about 14.4k lines of tests across 15 targets (one per module, plus a cross-module corpus suite). Two default-on rule packs ship day one, 81 ICU regex patterns between filesystem and git, and another 100 packs sit opt-in in the catalog. But it's macOS 26 and Apple Silicon only, and install.sh refuses anything else. It's hook-grade, not a sandbox, and it evaluates normalized text, not anything post-expansion.

If you're doing strict-concurrency Swift or thinking about hexagonal layouts in SPM, the repo is REPO_URL, and I'd genuinely like pushback on the module graph.
