rv: what I learned writing a 16-module Swift 6 package that blocks destructive agent shell commands

Strict concurrency, typed throws, and one Decision enum mapped to three hosts. The engineering notes behind a small Mac security tool.

Chris Karani·Aug 2026·DRAFT

I spent the last few months building a Swift tool called rv: a Mac-native guard that blocks destructive shell commands before coding agents like Pi, Grok, or OpenCode run them. It's on GitHub Pages if you want the longer story; this post is about the Swift engineering, because that's the part I'd want to read.

The shape of it: 16 SPM modules, strict language mode 6, one external dependency (argument-parser). Value types all the way down through the core: Domain, Engine, and Packs are structs and enums only. Classes exist at exactly two kinds of edges. Actors where shared mutable state is real (the allow-once store, the service runtime), and the XPC boundary.

Some things I'm pleased with:

Typed throws finally earning their keep. Regex compilation throws PatternCompileError with the offending pattern attached, and the compiler makes every call site deal with it. No try? swallowing a bad rule into silence; a malformed pack pattern fails loudly at load.

One Decision enum, three hosts. The interesting problem wasn't evaluation, it was mapping: Pi wants a TS extension, OpenCode a JS plugin, Grok a JSON hook file. Instead of per-host branching, there's one switch over a closed Decision enum in a hook mapper, with small host codecs turning the result into each host's native block format. Adding a fourth host means writing one codec.

Fail-closed as copy, not just behavior. An unreadable hook payload blocks the command, and the deny sentence lives in exactly one module shared by the hook layer and the TUI:

Blocked git reset --hard (core.git/reset-hard). Run it in Terminal, or rv allow-once.

No allow-because-XPC-missed either. If the daemon is down or versions skew, evaluation falls back to in-process rather than letting the command through. That constraint shaped a lot of the architecture.

The gate script might be my favorite unglamorous bit: tools/gate.sh infers which test targets to run from your git diff (touch RVEngine, run RVEngineTests) and refuses to exit green if it would run zero tests.

Numbers, since people ask: ~14k lines of source, ~14.4k lines of tests across 15 targets (one per module, plus a cross-module corpus suite). Two default-on rule packs ship day one, 81 ICU regex patterns between filesystem and git. Another 100 packs sit opt-in in the catalog. The engine itself is deliberately boring: normalize the command string (strip sudo/env wrappers), quick-reject on keywords, safe patterns first, destructive second, else allow. Default-allow on unknown commands, because two packs can't judge everything and a guard that blocks what it doesn't recognize gets disabled within the hour.

Honest limits: it's macOS 26 / Apple Silicon only (install.sh refuses anything else), it's hook-grade not a sandbox, and it evaluates normalized text, not anything post-expansion.
